# record-scope-test

Демо контекстного токена доступа: право выдаётся **на отдельные записи**, а не на модель
целиком. Открывается в панели как `Fixture → Record scope test`.

## Что внутри

Приложение владеет всем демо целиком, поэтому оно видно сразу после запуска фикстуры —
ничего не нужно докликивать в панели.

| Что | Где |
|---|---|
| Токен `record-scope-test` с `getOptions` и `check` | `RecordScopeTestApp.ts` → `setup()` |
| Две группы с разными срезами прав и их участники | `recordScopeSeed.ts` |
| Страница с матрицей доступа | `RecordScopeTest.tsx` |

Демо занимает первые 5 записей `Test` (по отсортированному id) и раздаёт их двумя
пересекающимися срезами:

| Группа | Записи | Кто состоит |
|---|---|---|
| `Test scope: alpha` | #1 #2 #3 | user1, user2 |
| `Test scope: beta` | #3 #4 #5 | user2, user3 |

`user2` состоит в обеих и видит объединение — права на записи складываются по группам так же,
как обычные токены. `pass` не состоит ни в одной и не видит ничего. Администратор проходит
любую проверку прав, поэтому под ним видны все записи — это не поломка демо.

Страница считает каждую клетку матрицы настоящим вызовом
`accessRights.hasPermission("record-scope-test", user, {testId})` — тем же, который делает
панель.

## Как это устроено

Группа хранит право не строкой, а объектом `{tokenId, rights: [...]}` — расширенная форма
`PermissionGrant`. `AccessRightsHelper` собирает `rights` со всех групп пользователя,
складывает их и передаёт в `check` токена; `getOptions` наполняет чекбоксы в форме группы,
так что этот же грант можно собрать руками в `System → Groups`.

Записи выбираются явно — ничего не выводится из связей. Наследование доступа по графу
связей — это отдельный механизм (`accessGraph`).

## Сид

`seedDemoData()` вызывается хостом (`fixture/index.ts`) после сида основной базы: гранты
ссылаются на id записей `Test`, а участники — на пользователей фикстуры, поэтому и то и
другое должно уже существовать.

Сид идемпотентен и самовосстанавливается: пересев фикстуры выдаёт `Test` новые uuid, поэтому
грант со ссылками на исчезнувшие записи перезаписывается, а не остаётся мёртвым. Пустая
таблица `Test` — no-op, страница в этом случае честно пишет, что демо-данных нет.

Проверено на обоих ORM (`npm run start:seed` и `npm run start:typeorm:seed`) — приложение
ходит в базу только через `runtime.models`.

## Сборка фронтенда

```
npx vite build --config fixture/apps/record-scope-test/vite.config.module.ts
```

Входит в `npm run build:apps`.
